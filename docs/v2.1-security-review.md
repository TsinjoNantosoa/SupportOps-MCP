# V2.1 security review

## Implemented controls

- MCP HTTP: constant-time optional Bearer verification, allowed Host/Origin lists, DNS-rebinding protection, bounded bodies, sessions and timeouts.
- Knowledge: allowlisted IDs and resolved-path containment.
- Ticketing: typed validation and parameterized SQL.
- Agent: no approval, rejection, SQL or shell tool; retrieved text is untrusted.
- Approval: n8n service authentication is separate from individual approver authentication.
- Identity: the API derives the actor from `SUPPORTOPS_APPROVER_TOKENS_JSON`; JSON `approver` and `X-SupportOps-Approver` have no authority.
- Decision: exact proposal, PENDING state, session, expiry, ticket version and idempotence are checked transactionally.
- Errors: raw messages, prompts, headers and credentials are not persisted by WF-07.
- Defaults: remote approval is false and no token is supplied in source.

## Tested attacks

Missing/invalid MCP bearer, unauthorized Host, unauthorized Origin, oversized body, unknown resource, path traversal, ticket/procedure prompt injection, untrusted controller, forged approver header, session mismatch, expiry, stale version, repeated/contradictory decisions, and secret-like audit content.

## Residual limitations

Individual bearer credentials suit only an isolated demonstration with secure provisioning. They do not provide federation, MFA, revocation UI or enterprise assurance. OIDC/SSO should replace them before real use. The n8n Wait URL is review UX only; possession is never approval authority. Remote approval must not be enabled automatically.
