# V2.1 demo guide

## Deterministic mode without OpenAI

Windows PowerShell:

```powershell
Copy-Item .env.example .env
docker compose up -d --build
docker compose ps
.\.venv\Scripts\python.exe -m pytest tests\test_e2e_v21.py -q
```

Linux:

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
.venv/bin/python -m pytest tests/test_e2e_v21.py -q
```

Demonstrate ticket/procedure retrieval over MCP, PENDING proposal, unchanged ticket, trusted CLI decision, atomic update, audit ID, and idempotent replay.

## n8n MCP runtime

Import the seven production files, configure network endpoints, then import the runtime-only fixture. Execute it manually. Its final item must contain:

```json
{"status":"PASS","ticket_id":"INC-1042","procedure_id":"outlook-send-failure","source_reference":"outlook-send-failure.md"}
```

## Optional OpenAI mode

Create the OpenAI credential inside n8n, select a tool-capable model available to the account, and ask: “Analyse le ticket INC-1042, consulte la procédure Outlook et prépare une note technique.” Verify tool calls, sources, PENDING state and no automatic approval. This was **NON VÉRIFIÉ** because no key was available.

## Approval demonstration

```powershell
uv run supportops proposals PENDING
uv run supportops approve PROP-XXXXXXXXXXXX
uv run supportops audit
```

WF-05 review intent cannot change the ticket. Do not enable remote approval unless the individual identity mapping was deliberately configured and authorized.
