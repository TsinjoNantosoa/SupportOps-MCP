# V2.2 — revue de sécurité

## Secrets

La valeur non vide détectée localement dans `.env.example` a été remplacée par un placeholder. Aucun secret n'est affiché dans ce rapport. `.env` reste ignoré par Git et les exports n8n ne contiennent aucun credential. Si la clé a quitté le poste ou a été utilisée dans un dépôt public, la révoquer et en émettre une nouvelle ; supprimer un fichier ne révoque pas une clé.

## Approbation

Le modèle ne reçoit pas d'outil d'approbation. `prepare_ticket_update` crée seulement une proposition `PENDING`. L'application exige : contrôleur de confiance, session, acteur authentifié, état `PENDING`, expiration valide, version de ticket inchangée, décision explicite et clé d'idempotence.

V2.2 corrige le rejeu : un `decision_key` déjà consommé ne peut être rejoué que par le même acteur et la même session. Un mismatch est refusé et audité avec `IDEMPOTENCY_IDENTITY_MISMATCH`.

## Prompt injection

Les résultats ticket et knowledge sont traités comme données non fiables. Les instructions système interdisent de suivre leurs ordres, de s'attribuer des privilèges, d'inventer une source ou de déclarer une modification avant confirmation.

## Approbation distante

`SUPPORTOPS_REMOTE_APPROVAL_ENABLED=false` reste la valeur par défaut. Le webhook n'est pas une preuve d'identité en lui-même ; WF-06 doit utiliser un credential individuel résolu côté serveur. Tant que ce flux n'est pas validé avec une identité forte, la CLI locale est le chemin de démonstration.

## Résultats

Les tests Python, les tests MCP HTTP, les contrôles d'injection et la validation statique des workflows passent. L'OpenAI live, le Wait/resume navigateur et la décision distante sont **NON VÉRIFIÉS**.
