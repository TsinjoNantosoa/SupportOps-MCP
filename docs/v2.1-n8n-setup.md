# V2.1 n8n setup

## Tested compatibility

- n8n image: `n8nio/n8n:2.45.7`.
- All seven exports imported and listed successfully.
- MCP Client 1.1 and MCP Client Tool 1.4 were checked against packaged node definitions.
- Runtime MCP calls to both Python services succeeded from an isolated n8n container.

## Endpoints

| Layout | Ticketing | Knowledge | Approval |
|---|---|---|---|
| Same Docker network | `http://supportops-ticketing:8001/mcp` | `http://supportops-knowledge:8002/mcp` | `http://supportops-approval:8010` |
| n8n on Windows host | `http://127.0.0.1:8001/mcp` | `http://127.0.0.1:8002/mcp` | `http://127.0.0.1:8010` |
| n8n container, Python host | `http://host.docker.internal:8001/mcp` | `http://host.docker.internal:8002/mcp` | `http://host.docker.internal:8010` |

## Credentials to create manually

1. OpenAI credential for a tool-capable model available to the project.
2. Optional MCP Bearer credential matching `SUPPORTOPS_MCP_BEARER_TOKEN`.
3. Service credential: `Authorization: Bearer <SUPPORTOPS_APPROVAL_API_TOKEN>` for WF-05 and WF-07.
4. Individual credential: `Authorization: Bearer <token mapped in SUPPORTOPS_APPROVER_TOKENS_JSON>` for WF-06.
5. Header Auth on the WF-06 webhook. Never put approver identity in request JSON.

Placeholder-only syntax:

```dotenv
SUPPORTOPS_REMOTE_APPROVAL_ENABLED=false
SUPPORTOPS_APPROVER_TOKENS_JSON={"demo-technician":"replace-with-a-long-random-secret"}
```

## Import and test order

1. Start Compose and wait for three healthy services.
2. Import `01` through `07`; keep them inactive initially.
3. Assign credentials without exporting them.
4. Test WF-02 with `INC-1042` and WF-03 with `Outlook sending issue`.
5. Test WF-04 only after assigning OpenAI.
6. Create a proposal and verify the ticket is unchanged.
7. Test WF-05 review intent; confirm it cannot apply a change.
8. Use the local CLI for approval by default.
9. Enable remote approval only after explicit authorization and identity-flow validation.

The reproducible fixture is `n8n/tests/runtime/runtime-mcp-e2e.json`. It contains no credentials and is not a production workflow.
