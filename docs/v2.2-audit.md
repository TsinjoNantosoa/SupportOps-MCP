## Résumé

L'audit a été exécuté dans le dépôt existant, sans push, commit, déploiement externe ni modification d'une instance n8n existante. Toutes les données de démonstration restent fictives.

## Sécurité des secrets

- `.env.example` contenait une valeur non vide ressemblant à une clé OpenAI dans le working tree. Elle a été remplacée par `replace-with-your-local-key` sans afficher ni recopier la valeur.
- `.env` est absent et ignoré par Git via `.gitignore`.
- Les exports n8n ne contiennent ni credentials, ni clé OpenAI, ni bearer token.
- Le scan des versions Git de `.env.example` ne montre pas de valeur non vide de clé OpenAI ; la valeur détectée était donc une modification locale non commitée. Une révocation reste recommandée si cette clé a été utilisée ou publiée ailleurs.
- Aucun credential n8n n'a été exporté ou modifié.

## Défauts confirmés et corrections V2.2

1. **Rejeu d'approbation insuffisamment lié à l'identité.** `ApprovalService.decide()` acceptait auparavant un même `decision_key` sans vérifier l'acteur et la session de la décision initiale. Le rejeu exige maintenant les deux identités et journalise un refus en cas de mismatch.
2. **Instructions agent trop générales.** Les instructions Python et n8n imposent maintenant l'usage des outils avant les faits, la séparation faits/hypothèses, les citations exactes, le bilingue FR/EN, les limitations et l'interdiction d'auto-approbation.
3. **Configuration d'exemple ambiguë.** `.env.example` ne propose plus de modèle par défaut non vérifié ; `OPENAI_MODEL` doit être rempli après vérification du projet OpenAI.
4. **Couverture de régression.** Des tests couvrent l'absence de clé réelle dans `.env.example` et les rejeux par session ou acteur différents.

## Limites restantes

- Le credential OpenAI doit être créé manuellement dans n8n ; sa valeur ne doit jamais être mise dans Git ou un export JSON.
- L'exécution payante OpenAI, les quatre scénarios chat, Wait/resume et le chemin de décision distante restent **NON VÉRIFIÉS**.
- L'approbation distante reste désactivée par défaut ; la CLI locale de confiance est le parcours de démonstration recommandé.
- La construction Docker a produit l'image locale mais la commande CLI n'a pas rendu la main dans le délai imparti ; `docker compose up --no-build` et les healthchecks ont ensuite fourni la preuve runtime.
