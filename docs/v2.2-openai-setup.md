# V2.2 — configuration OpenAI sûre

## Préparer la configuration locale

PowerShell :

```powershell
Copy-Item .env.example .env
notepad .env
```

Renseigner la clé uniquement dans `.env` ou un gestionnaire de secrets local. Ne jamais mettre sa valeur dans `.env.example`, un workflow exporté, un commit ou un log. Choisir `OPENAI_MODEL` seulement après avoir vérifié qu'il est disponible dans le projet OpenAI et qu'il supporte les appels d'outils.

## Credential n8n

Dans n8n, ouvrir **Credentials → New → OpenAI**, coller la clé dans le formulaire sécurisé et enregistrer. Ensuite, sélectionner ce credential dans les deux nœuds **OpenAI Chat Model** des workflows 01 et 04. La clé du backend `.env` n'est pas automatiquement disponible aux nœuds n8n.

Ne pas exporter le credential. Si le credential ou le modèle n'est pas accessible, laisser les scénarios OpenAI marqués **NON VÉRIFIÉ** plutôt que de contourner l'erreur.

## Contrôle des coûts

- Utiliser uniquement les tickets et documents fictifs `INC-1042` et `outlook-send-failure.md`.
- Limiter l'agent à un nombre borné de tours et d'appels d'outils.
- Tester d'abord les workflows déterministes 02 et 03.
- Exécuter un seul scénario OpenAI court, puis inspecter l'exécution n8n.
- Ne jamais lancer de boucle de retry non bornée ni de test massif.

`OPENAI_API_KEY` n'était pas présente dans l'environnement du processus et aucun appel payant n'a été lancé. La disponibilité de `gpt-5-mini` et la validité d'un credential n8n sont donc **NON VÉRIFIÉES**.
